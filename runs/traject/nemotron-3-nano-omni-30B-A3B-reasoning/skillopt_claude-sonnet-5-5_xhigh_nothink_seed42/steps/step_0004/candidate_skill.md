# Tool Calling Skill

## Rule 1: Output contract (an unparsable or malformed answer scores zero)
- `tool name` is the tool's full `### ` heading copied exactly, in the form `Provider: API` (e.g. `Arabic news API: Aljazeera`, `BestBuy Product Data: BestBuyProductData`, `Zappos Realtime Data: Zappos search product`). Never keep only the provider or only the API part.
- Output ONE flat list of call objects: `[{...}, {...}, {...}]`. Between objects put only a comma. Never put `]` or `[` between objects and never close the list early.
- Each call is its own object with exactly three keys, each appearing ONCE: `"tool name"`, `"required parameters"`, `"optional parameters"`. Never merge two calls into one object; two calls to the same tool are two objects. Put all optional parameters of a call in the single `optional parameters` list, since a repeated key overwrites the first. Use `[]` for an empty list; never omit a key.
- Both parameter keys hold a LIST of `{"name": "x", "value": "y"}` objects. Never use a dict such as `{"sku": "W1"}`. Every value is a quoted string ("1", "9098084", "true").
- Wrong: `[{...}], {...}]` or two `"optional parameters"` keys in one call. Right: `[{...}, {...}]`.
- Before finishing, check that the text ends with `}]</answer>` and that the brackets balance.

## Rule 3: Cover every clause in the query
- Before answering, list every atomic request: each sentence (including the FIRST, e.g. 'searched for X on Wayfair' is a product-search call), each comma or 'then / also / and / finally' clause, each list item, and each named provider or platform. Treat past-tense narration ('checking categories', 'explored regional settings', 'looked up details') as a request. Make at least one call per item, then re-read the first and last clause before finalizing.
- One phrase can name several calls. 'Asos categories and country availability' = categories/list AND countries/list. 'Financing options, images, and home services' = three endpoints. 'Specific store (ID, seller ID)' = the store endpoint with both IDs filled in.
- Vague or indirect clauses still need a call ('key company overview metrics', 'broader US mutual fund market environment', 'general global news'). Map each to the closest tool by function. A generic endpoint with a `function` or `q` parameter counts, e.g. function=OVERVIEW with the ticker.
- Every provider named in the query ('BestBuy, Wayfair, Zappos and Aliexpress') needs its own call on that provider's own endpoint, plus every detail call requested.
- N entities (ASINs, SKUs, emails, domains, IDs) for a one-value tool = N calls. A repeated action on different entities is repeated, not merged.
- Add no call for an aspect that no clause names (if asked for 'images and financing options', do not add pricing or warranty calls).

## Rule 4: Choose the tool whose name and inputs match the clause
- Match the query's verb, object and scope literally to the endpoint title and description. A dedicated list, detail, images, warranty, reviews, verify, current or similar-items endpoint beats a generic search. Examples: 'financing options' -> `get-financing-offers`; 'categories' -> `categories/list`; 'upgrades and downgrades' -> an upgrade-downgrade-history tool; 'details of a SKU' -> a detail tool, not search or autocomplete; 'verify' -> a 'Verify …' tool; 'disposable' -> a disposable-domain checker.
- When sibling tools look alike, decide by the inputs the query supplies. Pick the sibling whose schema lists those parameters (a postal code -> the sibling with `postalCode`; a price range or free shipping -> the search tool with price and shipping-filter parameters; region, metro area and city -> the tool with administrative-division fields, not a lat/lng tool). Never invent inputs such as coordinates, and never put a parameter into a tool whose schema lacks it.
- When siblings differ by hierarchy level, match the level to the tool's PARAMETER name, not just its title. A district code goes to the tool taking `kabupaten`, a province code to the tool taking `propinsi`, and a sub-district list to the Kecamatan tool. Use different siblings for different levels, not the same tool twice.
- A named outlet or source ('latest news from CNN') -> a by-source tool with the source as the value. 'General or global latest news' -> a recent/latest feed. An outlet with its own endpoint (BBC Arabic, Aljazeera) -> that endpoint. A named provider (Yahoo Finance, BestBuy, Zappos, Wayfair, ASOS) -> that provider's endpoint.
- For 'find X / show me some X' on a marketplace, use the item/product search endpoint, not shop-search, shop-items, review or store tools.
- When a provider has near-identical numbered variants ('Item Search' vs 'Item Search 3'), use the plain base endpoint unless the query clearly asks for several different searches.

## Rule 2: Parameter placement and values
- Copy placement from the chosen tool's schema. A name under 'Required parameters' goes in `required parameters`. A name under 'Optional parameters' goes in `optional parameters`, even when it carries the query's main input (`q`, `postalCode`, `storeId`, `sellerId`, `country`, `page`, `id`). If the schema says required parameters are none, `required parameters` is `[]`. Use only names that appear in that tool's schema.
- One query clause is one call carrying ALL of that clause's parameters (e.g. title and limit together). Repeat a tool only when the query gives it different inputs.
- Include every optional parameter whose value the query states or clearly implies. Examples: a postal code, store ID or seller ID in the query; 'first page' -> page `1`; '20 results' -> itemsperpage `20`; 'limit to 10' -> limit `10`; 'default sorting' -> sortby `0`; 'most relevant' -> sort_order `RELEVANCE`; '$600-$900' -> startPrice and endPrice; 'free shipping' -> the tool's shipping/switches filter; 'sorted by best sellers' -> the listed sort value. Do not invent optionals with no basis in the query, and never emit an empty value.
- A region or market qualifier ('US customers', 'US market', '$ prices') fills ALL locale-type optional parameters the tool has (country, region, currency, lang/locale), consistently, e.g. `US`, `USD`, `en-US`. Use the hyphenated form `en-US` for 'US English' unless the schema lists other codes.
- Copy values from the query's own wording and never replace them with a guess. 'BizToc's main page' -> page_id `main`, not `1`. IDs, SKUs, ASINs, ZIPs, emails, names and search terms are copied exactly. Keep topic words ('16GB RAM') inside the search text. When a type-like value has no listed options, use the query's own word ('seasonal', not 'season').
- Use the format the parameter expects. A marketplace `domain` takes the lowercase site suffix (US -> `com`, German -> `de`, UK -> `co.uk`). Follow any listed enum or code format. If a parameter description shows an example format (e.g. `filters=masterClID~180`), reuse its key format with the query's value.
- For hierarchical location fields, put each level in its matching field (country code, region, metro area, city) as the descriptions say.
