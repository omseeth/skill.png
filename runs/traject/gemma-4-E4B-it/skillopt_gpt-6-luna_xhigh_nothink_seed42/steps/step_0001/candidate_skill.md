# Tool Calling Skill

## Learned rules

- **Map each request to the endpoint that performs it.** Break a multi-part query into distinct requested operations, and record each operation's subject and constraints before choosing an endpoint. Keep each clause's values attached to the entity it describes. Choose an endpoint whose documented capability directly fulfills the request, using its exact `Provider: endpoint` name. Use a fallback only when it genuinely satisfies the action; do not choose a contradictory endpoint or add related calls merely because they share a topic.
- **Scope and bundle calls appropriately.** Make separate calls for distinct targets, checks, or purposes when they require distinct arguments. Combine multiple filters or categories in one call when they concern the same operation and the endpoint supports that syntax. Do not repeat a check, add overlapping searches, or introduce unrequested calls.

- **Handle independent calls and explicit sorting requests.** Issue calls for independent required operations together rather than waiting for one to finish when the tool interface supports it. If the user explicitly requests default sorting and the endpoint exposes a documented default-sort value, use that value; do not guess or add unrelated parameters.
- **Build arguments from the endpoint schema.** Use the exact parameter names and types, include every required parameter, and place parameters in the required or optional group specified by the tool. Carry requested or clearly implied constraints into the matching fields, including optional fields when they express a requested constraint; do not add unrelated options, defaults, or guessed values. Preserve query identifiers and values, converting them only to documented formats such as API codes, list syntax, or canonical enum spelling. Distinguish fields for different levels of a location hierarchy, and do not invent opaque identifiers. If a request implies a count or page and the endpoint exposes that parameter, use the smallest conventional value needed to fulfill it.
- **Validate the final response.** Follow the required response format exactly, including tool names, call-object keys, and any requested call ordering. Put parameters in the specified required and optional groups (such as `required_parameters` and `optional_parameters`), each serialized as an array of `{ "name": ..., "value": ... }` objects; include empty arrays when a group has no parameters. Check that every requested operation is covered, no unrelated call was added, and the JSON is valid. When the format requires only JSON, return no surrounding commentary.
