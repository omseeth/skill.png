# Mathematical Multiple-Choice Skill

## Core workflow: compare options exactly, never pick by gist (follow even when answering quickly)
1. Restate what the stem asks for: 'exact', 'strongest valid', 'complete list', 'equivalent to', 'for every', 'precisely when'. Note the conclusion type (existence, uniqueness, equivalence, bound, classification), every hypothesis and parameter range in the stem, and the quantifier order and type (for all / exists, uniform / non-uniform, subsequence / full sequence). Read each stated hypothesis as intended to be used.
2. Split EVERY option into atomic clauses: quantifiers (for all / exists / almost every), parameter ranges, constant dependence (C>0 vs C=C(p,q,n)), hypotheses used or dropped, function space or norm, domain, exponents and coefficients, index order, signs, strict vs weak inequalities, direction of implications, local vs global, and any 'moreover / conversely / only / even without / because' clause. When options share most of their text, only the differing clauses decide the answer. Mark which clauses are common to all options and decide each differing detail individually, not holistically.
3. Mark each clause TRUE / FALSE / UNSURE by derivation, a limiting or degenerate case, a small example, or a known theorem. Do not choose by which option looks cleanest, most general, or most impressive.
4. Discard any option containing a false or unjustified clause. Among the remaining options, rank by implication and choose the strongest one in which EVERY clause is justified. Also discard options strictly implied by another fully justified option.
5. Options are usually variants of one theorem: the true statement, truncated versions (a conclusion dropped), inflated versions (an unproved extra clause, sharper constant, weaker hypothesis), and altered versions (wrong hypothesis, quantifier, or direction). Identify which kind each option is.
6. Do not default to the bare, minimal, or hedged option because it feels safe.
7. Commit once exactly one option survives (not false, not strictly weaker than another survivor, no unjustified extra clause). Do not switch to an option that merely looks more general or elaborate unless its extra content is justified.

8. Hub test: 'strongest valid' means strongest PROVABLE, not 'most clauses'. Locate the hub, the option from which every other option follows by one small edit (add or drop a clause, swap two symbols, shift an exponent, reverse a direction). The true statement is usually the hub, or the hub plus a clause you can actually derive. Override the hub only on positive evidence.
9. FALSIFY before ranking by strength. Strength only breaks ties among options whose every clause survives a concrete test. The correct option is very often the plain, natural statement of the source theorem, stated in the stem's own vocabulary, and the wrong one adds or alters a rider (a new object not named in the stem, e.g. a 'decorated' tree, a 'free factor', 'the minimiser has least energy', 'moreover ... unique'). You must be able to prove any extra clause in a few lines. For each differing or extra clause run at least one test:
   - Cheap invariants: rank, dimension, cardinality, degree and size bounds (a free factor of F_n has rank ≤ n, so it cannot also have rank ≥ 2n-2 > n for n ≥ 3), degenerate cases. A clause failing such a check is the corruption.
   - Zero/homogeneous data: an estimate 'bounded only by the data norms' forces the solution to vanish when data = 0 (uniqueness). A genuine local regularity estimate must also contain a lower norm of the solution itself on a larger set. A bound with data only is an inflated distractor, and bare membership in the space is the faithful claim.
   - Scaling/normalization: before accepting 'unique' vs 'unique up to scaling/ray/normalization', check whether the invariant is actually homogeneous of degree 0 in the stem's setting. Do not add a ray clause unless the invariant is scale-invariant.
   - Generic infinite example: for summability/weight conditions (sum N_c vs sum c·N_c), ask whether the condition is satisfiable for a generic infinite-rank or infinite-family case. A total-count condition that forces finiteness is false. Prefer the weighting that matches the natural conserved or controlled quantity.
   - Exhaustiveness of 'either A or B' outputs: run the algorithm or statement on degenerate inputs (bipartite graph, no cycle, all cycles even, empty set). If some input satisfies neither branch, the option is false. Read a plain 'finds X in time T' in the standard sense (finds one whenever one exists, otherwise reports none) and do not reject it for omitting a trivial qualifier when the competitor fails exhaustiveness.
   If a rider survives no test you can run, drop that option even if it looks sharper. Do not over-correct: prefer a stronger option only when its extra content is derivable (see strength calibration), never merely because it is longer or adds structure.
10. Strength ladder (use when options are nested variants, and always for 'strongest / exact / complete' stems): after step 9, order the surviving options by logical implication (e.g. 'tends to 0' < O(f) < explicit constant < exact asymptotic; 'finitely many' < 'at most N'; 'some alpha' < 'alpha = s'; base statement < base plus extra clause). Take the highest rung whose every extra clause you can justify against the stem's hypotheses, and do not stop at a lower rung merely because it is safer. If an option is the base statement minus a qualifier the construction obviously provides (invariance, uniqueness, the full range, the converse), it loses to the base statement. Do not climb past the first rung that adds unproved sharpness (a better constant, a shaved log, uniformity in a parameter, an extended range or exponent, a 'moreover' clause). The answer is the pivot between 'true but weaker' and 'sharper but unjustified'.

## Recognising corrupted or inflated distractors
- A distractor is usually a true theorem with one targeted corruption: a dropped or added hypothesis ('even without the hypothesis', 'even if the base locus is non-simple'), a condition stated for a different parameter, prime or object than the one assumed, a shifted exponent or index, strictness imposed where equality must occur (e.g. strict inequality on a plateau), a restricted range plus an invented counterexample clause, an 'only asymptotic / only local / only short time' downgrade, a swapped necessary/sufficient direction, or a replaced hypothesis (e.g. n≡2 mod 4 instead of 4 | n).
- Quantifier shifts: 'for some' vs 'for every' vs 'unique'; 'there exists' vs 'can always be chosen'; 'for all N' vs 'for large N'. Probability wording: 'positive probability' vs 'almost surely' vs 'probability 0'.
- Relation swaps: equality vs inclusion (⊆ vs =), conjugation of sets vs of generated subgroups, the global group vs a smaller ambient subgroup, decidability vs explicit construction of witnesses. Distinguish existence in a specific ambient space or dimension from existence in some space.
- An extra clause is acceptable only if it is derivable and consistent with equality cases. If it asserts a failure or new phenomenon you cannot justify, treat it as the corruption. Test the extra clause separately. Be suspicious of extras that add structure, sharpness, or automaticity beyond the natural statement ('moreover, one may take the endpoint value', 'can be obtained from only the base data', 'once entered it can never leave', 'the original structure must coincide with the new one'). Prefer the clean statement covering the full stated range over a variant that restricts the range and adds a counterexample.
- Options with specific numerics (explicit asymptotic coefficients, exact constants, extra sign or monotonicity claims, a 'moreover' clause on large-time behaviour) are the typical inflated distractors. Keep one only if you can derive the extra detail.
- Properties in limits: reject options saying a defining condition (Einstein constant, normalization, invariance) 'need not persist' in a limit when the setting fixes it and compactness arguments typically preserve it. Ask directly: does the property pass to the limit? Is the limit global or only local? Is the threshold explicit?
- For numerical-bound questions (kissing numbers, packing densities, etc.), 'strongest that holds' means the best bound actually established. Larger numbers are often fabricated over-claims. Anchor on the best known bound you can recall, and be sceptical of any lower bound above the known record.
- A 'complete classification' or rigidity question often has a simple answer (e.g. only the obvious or Killing ones). Do not pick an option that invents extra modes, families, or larger kernels unless a dimension or eigenvalue count supports it. A complete classification should cover all regimes of the stated parameter with consistent claims in each.
- Treat glosses with suspicion: 'equivalently', 'in particular', 'the hypothesis can be replaced by a simpler one', 'the same conclusion holds for any...'. Check that the gloss is truly equivalent to or implied by the main claim. A simpler hypothesis such as 'd > 2k' in place of an explicit threshold is generally a different, stronger claim.

## Strength calibration (two-sided): the answer must be true AND maximal
- If the stem says 'exact', 'precisely', 'complete description', or 'strongest valid', a true but weaker corollary loses to the option giving the full explicit formula or characterization. 'The quantity is rational' is weaker than 'the quantity equals an explicit expression'. If a stronger option adds a natural consequence you can derive from the stated hypotheses (injectivity, separation of points, finiteness, uniqueness, a matching lower bound, a global rather than local statement), that option is the answer.
- Typical weak-vs-strong pairs: finite-time blow-up > 'unbounded / not globally bounded'; weak mixing > ergodicity; 'fully residually free' > 'residually free' or 'limit group'; 'all periods lie in algebra S' > 'some finitely generated subalgebra of S contains them'; a full limit object (with its metric or equation) > only parameter convergence; an explicit threshold with bound > 'there exists some threshold'; a refined statement (e.g. trapezoidal plus strict log-concavity off the plateau) > the bare one, provided the refinement is self-consistent. Check whether the stem's hypotheses reach the upper member; if so, pick it.
- Conversely, an option that looks stronger loses if any added piece is unsupported. Typical over-claims: 'conversely, every such value occurs'; 'holds for every set / parameter' where only a restricted class works; a false or irrelevant 'because ...'; a dropped parameter dependence; a conclusion like 'equals 0' or 'is always projective' that the hypotheses do not imply; a local or conditional conclusion upgraded to global or unconditional; a sharpened constant (6 -> 5); a closed endpoint; extra properties asserted of the limit. The regularity of the conclusion should match the regularity of the data, and localized or boundary problems typically give only local smoothing.
- The right answer usually keeps the exact quantitative content and the natural qualifiers of the source result (e.g. 'locally' homogeneous limits, an explicit threshold together with its bound).
- For generalized or weak notions (generalized derivatives, relaxed continuity, weaker compactness or projectivity), classical conclusions such as vanishing at extrema, 'true for all index sets', or exact equality may fail. Check whether the notion really gives equality or only an inequality, and whether the property extends beyond the countable or separable case.

## Near-duplicate options: constants, quantifiers, ranges, exact details
- When options differ only in a constant (1 vs sqrt(n), gcd vs sum, a+1 vs a, n/2 vs (n-1)/2), a divisor condition (divides m vs 2m, even divisor, m1≠1), or a normalization (v vs v/||v||), compute the correct value yourself with Cauchy-Schwarz, a small case such as n=1 or n=2, or a degenerate case (a parameter = 0). Prefer the option whose differing detail you derived. Recompute any displayed numerical approximation from the closed form, and watch for swapped logarithm bases (log_a b vs log_b a) and wrong denominators.
- 'There exists C>0' vs 'C=C(p,q,n)', 'for every a>1' vs a fixed a, and a restricted vs full range are different statements. Check what the stem supplies and which parameters a constant may depend on. Constants or neighborhoods that depend on a parameter can sometimes be absorbed by shrinking the neighborhood, so a constant-free form is not automatically too strong. Equally, a vague 'some C' is often a weakened distractor. Decide by checking against the stem, not by default.
- Uniformity: a fixed-t bound is weaker than a uniform-in-t bound, and 'uniformly for all parameters' needs a bound valid for every value, not only asymptotically. For two-sided estimates, prefer matching rates (same function in lower and upper bound) when the sharp or strongest uniform statement is asked, and reject mismatched exponents or one-sided bounds. A statement with explicit constants or exponents and a statement of mere positivity are not interchangeable.
- Check limsup vs liminf, '<' vs '<=', and 'if' vs 'precisely if'. Prefer the characterization that is genuinely iff and uses the natural blow-up quantity.
- Respect the stem's exact parameter range. If it says 'for every 0<β<c', reject options that silently extend to the endpoint (≤ c) or beyond (e.g. 1/κ instead of 1/(2κ)). The option that states the conclusion for the stem's own β without altering the range is usually the faithful one.
- Reject options that restrict to one test vector or special case when the stem asks for a general statement, and options that add an existence or 'conversely' claim when the base statement already answers the question.
- If two options look equivalent under the stated ranges (e.g. 'm=2' vs 'm≡2 mod n' when 0≤m<n), re-read for a subtle difference. If they are truly equivalent, prefer the one in the problem's native modular or structural language.

## Tie-breaker: signature of the winning option
- The correct option usually (i) uses every hypothesis and parameter range of the stem and no more, (ii) states all parts of the natural theorem (existence AND uniqueness; convergence case AND divergence case; the full inequality with its matching lower bound), (iii) has the same quantifier order and scope as the stem, and (iv) contains no explicit rate, constant, or dependence list that you cannot derive.
- Scope and quantifier-order inflation: treat the following as corruptions unless derivable. (a) Generalizing the stem's class (2-colorings becoming 'every finite coloring'; fixed d, k becoming all d, k). (b) Swapping quantifier order (∃y ∀coloring vs ∀coloring ∃y; ∃C before ∀ε vs C=C(ε)). (c) Shifted indices or ranges (k to k+1, N≥2 to 'N large', closed to open endpoint). (d) 'Every f' or 'every r' replacing 'generic f' or 'almost every r'. (e) An equality replaced by a strict or one-sided inequality.
- For 'generic' (Baire) or 'almost every' results, 'every element' versions are usually false, and one-sided or strict versions are usually too weak or wrong. Keep the quantifier structure and natural exponent or threshold of the source theorem.
- For criterion, zero-one or 'iff' stems, prefer the two-sided dichotomy in the plain quantity named in the stem over versions that add side conditions (extra growth conditions, log factors, special parametrizations) and over one-direction-only versions, subject to the rule that the missing direction must be derivable.

## Final sanity pass (do this before committing)
Name the option you would pick and the runner-up. State in one sentence the single clause on which they differ. Then give an explicit derivation or concrete test for that clause (zero data, small case, scaling, degenerate input, count or dimension check). If your choice carries the extra, more specific, or more elaborate clause and you only have a plausibility argument for it, switch to the plainer option unless that option is demonstrably false or strictly implied by a fully proved alternative. Conversely, if you are leaning to a trivial, bare, or negatively hedged option, confirm that it is not just the weakened corruption of a positive option whose extra content you can derive.

## Trivial directions, negative hedges, iff vs one-way, FPT vs XP
- If an option is the trivially true direction (isomorphic ⇒ same invariant, a result true for any graph, a general fact), it is almost never the answer to 'what is the role of invariant X in classifying / distinguishing / determining'. The intended theorem is the nontrivial direction (X determines the object, up to the stated equivalence). Ask: would a paper highlight this statement? Then check that the nontrivial direction is plausible under the stem's hypotheses, and that the option does not drop or add hypotheses.
- Option tails of the form 'only ...', 'not ... one', 'need not ...', 'does not provide ...', 'non-uniform' assert that no better result exists or add a non-improvability claim. A positive-theorem source rarely proves this. Treat such tails as the downgrade corruption and prefer the positive option they weaken.
- Algorithmic bounds: f(k)·n^{O(1)} (FPT, e.g. 2^{O(k)} n^{O(1)}) is strictly stronger than n^{O(k)} (XP) and than 'polynomial for each fixed k'. Among running-time options that are all true, the strongest is the best bound; choose the FPT bound if the stem's hypotheses support it, and distrust claims that the result is 'only XP' or 'not FPT'.
- 'A iff B' beats 'A ⇒ B' and 'B ⇒ A' when the stem asks for the strongest characterization and the missing direction is derivable from the stem's hypotheses (e.g. a natural construction realizes every admissible parameter value). If the converse or realization claim is not derivable, it is an over-claim, not a strengthening. Reject iff-variants that change the condition (K vs O, a different range such as n=2 beyond the stem's n>2) or add a 'same without change' extension.

## Using stem hypotheses as clues; odd-one-out swaps
- A threshold hypothesis in the stem (e.g. 'γ>1', 'p>2d/(1+2d)', 'n>2') is usually exactly what the stated conclusion needs. If options differ in an exponent such as u^{-γ} vs u^{-(γ-1)}, ask which exponent is meaningful (positive, integrable, decaying) exactly on the stem's range; the answer is typically the one whose validity range matches the hypothesis. Also sanity-check the exponent by a simple heuristic (first moment, scaling, dimension count) instead of recalling a template such as 'Kesten tail ~ u^{-γ}' without checking the model.
- When options differ only by where a coefficient or index sits (λ on the s_1 term vs the s_2 term, A before B, i vs j), count how many options use each placement. If one option is the isolated swap and all others agree on the other placement, the swap is the corruption (distractors are single edits of the truth and so mostly inherit its details). Confirm with the stem's naming order or a limiting case (a parameter → 0) when possible.

PRIORITY RULES (apply before the generic workflow; they decide near-ties that the generic rules have been getting wrong). Write out the comparison explicitly even when answering quickly. All seven persistent errors so far were answered by gist.

0. Two opposite mistakes keep happening. Avoid both.
  (A) Choosing the truncated or corollary option (bare membership, 'is rational', 'not globally bounded', only the first clause of a theorem) when a fuller option is derivable.
  (B) Choosing an option whose extra content deletes a stem hypothesis, shifts an exponent or range, or is an unconditional rider.
  Do not decide by length. Classify what each option adds relative to the plainest option, using rules 1-2.

1. LEGITIMATE upgrades: take them over the truncated option.
  a) An explicit formula for the very quantity the stem names, when the stem says 'exact', 'which exact statement holds for every ...', or 'strongest'. If the weaker option is a corollary of the formula option ('in particular / therefore it is rational / an integer / finite'), the formula option is the answer. Test the formula on the smallest or a degenerate case (e.g. a path with one anchor, gcd=1, n=1). Take it unless the test refutes it.
  b) A stronger mode of the same conclusion. 'Blows up in finite time' beats 'is unbounded / cannot remain globally bounded / not globally bounded'. 'Strongest statement about existence behavior' in blow-up or Keller-Segel-type PDE stems means the finite-time blow-up statement, when the rest of the option text (initial-mass condition, functions M_1, M_2, ranges) is identical.
  c) A trailing 'Moreover, if [new hypothesis H stated in the option], then [consequence]' attached to a first clause identical to the weaker option. H is stated inside the option, so the clause adds a conditional result without changing the stem's hypotheses. The bare first-half option is then the truncated version and loses under 'strongest'. Only check that the consequence is natural under H (e.g. separating points plus a rational image gives a rational point, so the equality of sets follows).

2. CORRUPTING riders: reject.
  a) Any 'even without / regardless of / for every ...' that deletes or relaxes a hypothesis the stem explicitly assumes. The stem lists a hypothesis because the theorem uses it. An option that makes it redundant is the distractor, however 'strong' it looks. If the stem assumes H and an option says 'even without H', discard it. Prefer the plain statement of the conclusion.
  b) A changed range or endpoint, a different parameter, or specific numerics, constants, rates or exponents you cannot derive.
  c) Unconditional new objects or properties absent from the stem.
  The test separating 1 from 2: an upgrade is stated in the stem's own objects, keeps every stem hypothesis, and survives a small test. A corrupting rider drops or changes a stem hypothesis or range, or is unverifiable.

3. 'Equivalent to' / 'iff' stems. The correct option must be a genuine two-sided equivalence.
  - An option that tests a narrower class of objects (adds side conditions such as G(N)∩M=N, saturated, closed, 'for some') or concludes something stronger is only implied by the target, not equivalent. Reject it.
  - If the stem explicitly defines a term (e.g. 'undermonoid', 'anchor', 'limiting periods'), the correct option almost always uses that term verbatim, in its plain form ('every undermonoid of M is an FFM'). A defined-but-otherwise-unused term is a strong cue. Do not swap it for a more technical-looking variant.

4. Exponents and thresholds. When the stem has a threshold hypothesis such as γ>1 and options differ as u^{-γ} versus u^{-(γ-1)} (or similar), pick the exponent that becomes positive exactly at the threshold. Here that is u^{-(γ-1)}, i.e. u^{-γ+1}. This matches the classical ruin-with-risky-investment result, where the tail exponent is (2a/σ² − 1), one less than the naive ratio. Do not use 'Kesten tail ~ u^{-γ}' from memory. Check which exponent the hypothesis actually makes meaningful.

5. Logically equivalent options. If two options are identical under the stem's ranges (e.g. 'm=2' versus 'm≡2 (mod n)' when 0≤m<n and n≡0 mod 6, so n≥6), choose the one written in the same native language as the other conditions (the congruence form, parallel to 'n≡0 (mod 6)'). Do not pick the literal-looking 'm=2' just because it is simpler.

6. Before committing, name the two finalists and say which is a prefix, corollary or narrowing of the other.
  - If the extra content is a formula for the named quantity, a stronger conclusion class, or a conditional 'Moreover, if H then ...' clause that passes a small check, choose the fuller option.
  - If the extra content deletes a stem hypothesis, extends the range, or adds unverifiable numerics, choose the plainer option.
  - Never choose the bare 'is rational / is bounded / is in the space' option when another option contains that same statement as a consequence of something derivable.

Keep reinforcing what already works: every stable success followed the generic clause-by-clause workflow, so keep splitting options into clauses and testing only the differing ones.
